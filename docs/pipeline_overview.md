# AAOCA 基础流水线与当前快照

## 1. 这条流水线做什么

基础流水线把患者索引表与医院导出的临床 PDF 转换为可追溯的文档、页面、section 和患者时间线。它负责保存来源、识别重复文件、关联患者、提取或 OCR 文字、划分文书、识别日期并生成质量检查材料。

它不直接给出临床真值，也不把“计划手术”“知情同意”“诊断性造影”自动当成已完成的 AAOCA 手术。相关性复核和实际治疗整理分别由后续模块完成。

## 2. 当前正式快照

当前正式快照位于 `data/derived/v0.1_full/`。2026-10-14 完整重建后的聚合规模为：

| 项目 | 当前数量 |
|---|---:|
| 队列患者 | 232 |
| PDF 来源路径 | 365 |
| 去重后的 PDF 内容 | 342 |
| 页面 | 13,485 |
| sections | 13,931 |
| 患者时间线记录 | 10,341 |

其中 341 份唯一 PDF 可以关联到 231 位患者；一位患者在当前输入范围内没有 PDF，一份 PDF 不属于现有队列。23 个来源路径是其他文件的完全重复副本，仍保留在来源清单中，但不会重复生成临床 section。

当前有 10,362 个 section 带日期；其中 21 个来自未匹配到队列患者的那份 PDF，所以患者时间线只包含 10,341 条记录。两个数字描述的是不同范围，不能互换。

正式快照已通过结构、来源和交叉引用检查。这个结论说明输出内部一致且可回到来源，不代表 OCR、分段、日期或临床语义已经达到人工金标准。

## 3. 处理流程

### 患者与文档关联

关联优先使用稳定的住院号、门诊号、文件名和医院导出页头中的明确标识。遇到多个患者冲突或来源证据不一致时，文件进入隔离或复核队列，不使用姓名模糊匹配，也不从临床正文中的任意数字猜测患者身份。当前队列中有一组患者共享同一非占位门诊号，另有少量页头、文件名或内部标识不一致；它们依靠更稳定的住院号和来源证据关联，同时保留 QC 提示供数据提供方核对。

原始标识只保留在受限的本地 linkage 文件中。流水线使用的伪名化患者编号便于跨表连接，但不应被当作可公开的匿名化证明。

### 文字提取与本地 OCR

数据中存在两类 PDF：Safari 导出的文档通常有可用中文文本层；Chrome/Quartz 导出的许多文档把中文保存为矢量轮廓，只能提取到少量数字和拉丁字符。更换普通 PDF 解析库无法恢复这些轮廓字的语义，因此流水线只对需要的页面运行本地 OCR。当前基线使用 RapidOCR 3.9.2 与 PP-OCR v6 的本地 CPU 模型。

首次完整处理有 8,216 页进入 OCR，8,202 页得到非空文字，14 页仍为空。在当前四进程、每进程两个推理线程的 CPU 配置下，首次全量 OCR 约需 2.4 小时；完成后的文档级缓存可供后续重建复用。OCR 结果与原始文本层分开保存，并保留行位置和置信信息。低置信度只用于提示复核，不能解释为临床正确率。密集检验表中的项目、结果、单位和参考范围尚未形成经过人工验证的单元格关系。

### 规范化、分段与日期

规范化保留页边界，只清理可明确识别的浏览器导航、打印页眉和空白噪声。被移除的内容有可回溯记录，原始文字不会被覆盖。医院导出中有 132 份 PDF、2,602 页包含超出标准页面边界的文字；提取器会保留并标记这些内容，避免默认裁剪造成静默丢字，但仅凭坐标不能判断它是否应当可见。

分段规则识别入院、病程、出院、操作、会诊、门诊、检验、行政和非临床内容。每个非空规范化文本行恰好归入一个 section；无法可靠识别的内容仍保留，不会被丢弃。当前规则已补充多报告检验页、结构化门诊表单和受损页面后的非临床片段。

日期优先来自文书标题、明确文书字段或检验时间列。出生、入院、打印、采样、计划操作和历史日期与事件日期分开保存。冲突日期、OCR 日期和无法判断的日期保持不确定，不从相邻 section 借用，也不把打印时间当成临床事件时间。早期检验页曾因跨页排版把浏览器打印时间误当成结果日期；当前规则同时使用页面位置与检验时间列，并支持只有日期、没有时分的合法值。

## 4. 主要输出怎样使用

| 输出 | 适合回答的问题 |
|---|---|
| `patient_manifest.csv` | 每位患者是否有来源文档、页面和 section。 |
| `document_index.csv` | 每份 PDF 的匹配、重复、提取和 OCR 状态。 |
| `page_index.csv` | 哪些页面使用原生文字或 OCR，哪些页面需要复核。 |
| `section_index.csv` | 每个 section 的类型、日期、页码和来源定位。 |
| `patient_timeline.csv` | 按文书事件日期排列的 section 级时间线。 |
| `date_mentions.csv` | 文书日期与正文中其他日期的区分。 |
| `sections/` | 带完整文字和定位信息的 section 数据，供证据抽取与人工回看。 |
| `qc/` | 未匹配来源、空页、未知日期、OCR 待复核和其他质量问题。 |
| `private/` | 仅限本地使用的直接标识关联材料。 |

时间线是“带日期的文书 section 序列”，不是已经核实的临床事件真值。日期筛选也不是天然无泄漏：当前仍缺少可靠的 `available_at`，早期日期的回顾性文书可能包含后来发生的结局。

## 5. 运行与验证

`pipeline.ocr.json` 通过 `AAOCA_PDF_ROOT` 指向受限的完整 PDF 根目录。运行前必须先设置该环境变量；不设置时只能看到仓库内的样本目录，无法复现上面的正式规模。

```powershell
$env:AAOCA_PDF_ROOT = 'E:\path\to\AAOCA Cases'
python -X utf8 -m aaoca_pipeline --config config/pipeline.ocr.json
python -X utf8 scripts/validate_outputs.py data/derived/v0.1_full `
  --report data/validation/validation_v0.1_full.json
```

验证报告属于机器回执，统一写入 Git 忽略的 `data/validation/`，不再放入 `reports/`。新增一批同格式资料时，应新建输出目录完成试跑和检查，再决定是否替换正式快照；不要手工修改生成的索引、section 或时间线来“补数据”。

## 6. 当前限制与下一步

- [Gold Set](gold_set_evaluation.md) 已固定抽取，但尚未完成人工标注，因此不能报告 OCR、分段、类型或日期的真实准确率。
- 14 个 OCR 页面仍为空，密集检验表仍需专门的表格核验。
- 文书日期不等于信息可用时间；建立建模 cutoff 前必须定义 index decision 与 `available_at`。
- 未匹配 PDF、缺失 PDF 和标识冲突需要数据提供方确认，不能靠正文猜测修复。
- 实际 AAOCA 管理和手术状态必须使用独立的证据规则与人工复核，详见 [AAOCA 实际治疗与手术整理](aaoca_management.md)。
